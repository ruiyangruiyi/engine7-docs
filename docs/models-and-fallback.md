# 模型选择与 Fallback

[返回文档首页](../README.md) · [English](en/models-and-fallback.md) · [任务干预命令](interactive-tasks.md)

Engine7 把伙伴的持久状态与模型选择分开。模型服务负责当前推理；工作区中的配置、记忆与文件随部署环境保存。你可以按任务选择模型，也可以配置备用模型或服务，提高服务可用性。

## 先看当前状态

```text
/model
```

该命令列出已经配置的模型。自动路由使用备用链时，还会显示链顺序、下一请求的候选项、冷却中的服务及上次实际使用的模型。

列表来自你的部署配置，不能通过输入一个未配置的模型名称直接开通服务。

## 手动选择模型

从 `/model` 返回的列表中复制完整模型引用，或使用已经设置的别名：

```text
/model 已配置的模型引用或别名
```

原生斜杠命令平台请将引用填写到 `model` 参数中。出现多个匹配项时，使用完整引用。

手动选择是临时覆盖自动路由。如果正在执行任务，切换可能打断旧模型查询；先确认任务进展再切换，通常更容易接续。

## 自动备用链如何工作

当部署中配置了备用候选项，主模型或服务遇到可触发切换的错误时，引擎可以继续尝试链中的其他模型或服务。失败的候选项会进入各自的冷却期，避免不断重复请求同一个不可用服务。

备用项需要提前配置、具备有效凭据与额度，并适合相应任务。不同候选项在工具、视觉、上下文容量和输出效果上可能存在差异。

这里的目标是**最大限度保持可用**。所有候选项都不可用，或任务依赖的其他服务失败时，仍可能需要人工处理；备用机制不会把每次任务变成成功保证。

## 恢复自动选择

```text
/model auto
```

该命令清除手动模型覆盖，恢复配置中的自动选择，同时清除备用链冷却状态。`/model reset` 也可执行这一操作。

服务恢复后如需重新尝试，可以先 `/model auto`，再 `/model` 确认状态。此前已经完成的任务动作不会因为模型重置而被撤销。

## 配置建议

1. 在安装器／控制台或部署配置中添加模型服务、有效凭据和模型标识。
2. 配置主模型及备用候选项，并分别确认能够响应实际请求。
3. 用 `/model` 检查是否进入自动选择以及链顺序是否符合预期。
4. 重要任务先确认模型是否支持需要的工具、视觉或上下文容量。

遇到无法切换、全部冷却或服务报错，见 [FAQ](faq.md)。
